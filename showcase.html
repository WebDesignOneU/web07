Fetch API & Datos Externos

Consumo de APIs REST con fetch() y async/await. Manejo de errores con Swal.

PokeAPI
Pokédex — Fetch + Async/Await
Busca cualquier Pokémon en la PokéAPI. Prueba: pikachu, charizard, gengar.
⏳ Buscando...
js/blocks/red.js
async function buscarPokemon() {
  try {
    const res  = await fetch(`https://pokeapi.co/api/v2/pokemon/${nombre}`);
    if(!res.ok) throw new Error('No encontrado');
    const data = await res.json();
    mostrar(data);
  } catch(e) {
    Swal.fire('Error', e.message, 'error');
  }
}
Concepto
¿Cómo funciona Fetch?
Flujo de una petición HTTP asíncrona con manejo de errores y parsing JSON.
1️⃣
fetch(url)
Hace la petición HTTP GET.
2️⃣
await res.json()
Parsea la respuesta como JSON.
3️⃣
try / catch
Captura errores de red o datos inválidos.

    JavaScript Avanzado — De Scripts a Motores

    Arquitectura en cuatro capas: Modelo → Red → Procesamiento → Resiliencia. Encapsulamiento, asincronía, pipelines funcionales y tolerancia a fallos.

    1 · Modelo
    Clase ES6 con encapsulamiento
    Clase Producto con campo privado #precio, getter/setter que valida, método de negocio encadenable y serialización con toJSON().
    js/core/model.js
    class Producto {
  #precio;                       // campo privado real

  constructor(id, nombre, precio) {
    this.id     = id;
    this.nombre = nombre;
    this.precio = precio;      // pasa por el setter
  }

  get precio() { return this.#precio; }

  set precio(valor) {
    if (valor < 0) throw new Error('El precio no puede ser negativo');
    this.#precio = valor;       // invariante del dominio
  }

  aplicarDescuento(pct) {
    this.precio = this.precio * (1 - pct / 100);
    return this;                 // encadenable
  }

  toJSON() { /* id, nombre, precio */ }
}
    2 · Red
    ProductService — fetch + async/await
    Capa de servicio que consume una API real y convierte el JSON plano en objetos de dominio. Observa el ciclo de la Promise.
    pendingen vuelo…
    fulfilledresponse.ok
    rejectedthrow / catch
    // esperando ProductService.getProducts()…
    💡 fetch() no rechaza ante un 404/500: la Promise se cumple. Por eso hay que validar response.ok.
    js/core/model.js
    class ProductService {
  constructor(baseURL) { this.baseURL = baseURL; }

  async getProducts() {
    const res  = await fetch(`${this.baseURL}/products`);

    // fetch NO lanza error en un 404/500
    if (!res.ok) throw new Error(`HTTP ${res.status}: ${res.statusText}`);

    const data = await res.json();

    // JSON plano → objetos de dominio
    return data.map(item => new Producto(item.id, item.title, item.price, item.category));
  }
}
    3 · Procesamiento
    Pipeline filter → map → sort → reduce
    Cada etapa tiene una única responsabilidad y ninguna modifica el arreglo original. Cambia el filtro o el descuento y la tubería se recalcula.

    ▼
    sort((a, b) => b.precioFinal - a.precioFinal)
    ▼
    reduce((t, p) => t + p.precioFinal, 0)

    4 · Resiliencia
    Retry + Timeout + AbortController
    Una API puede tardar, caerse o devolver errores. fetchWithRetry() reintenta con exponential backoff y cancela si el servidor no responde a tiempo.
    💡 Ver el AbortController: deja latencia 4000 y timeout 800 → se cancela por tiempo. Backoff: 1000 → 2000 → 4000 ms.
    js/core/http.js
    async function fetchWithRetry(url, opciones = {}, reintentos = 3, timeout = 5000) {
  for (let intento = 1; intento <= reintentos; intento++) {

    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), timeout);

    try {
      const res = await fetch(url, { ...opciones, signal: controller.signal });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return await res.json();

    } catch (error) {
      if (intento === reintentos) throw new Error('Falló tras varios intentos');

      const espera = 2 ** intento * 500;   // backoff exponencial
      await new Promise(r => setTimeout(r, espera));

    } finally {
      clearTimeout(timer);
    }
  }
}
